Welcome

Thank you for testing this reference implementation of the MSRMF framework.

This tool was developed to support pilot evaluations of the framework described in the accompanying research paper.

Estimated time: 10–15 minutes.

What this tool does

  • ✔ Classify engineering changes
  • ✔ Decide what enters a release
  • ✔ Document justification
  • ✔ Plan for rollback
  • ✔ Track deployment
  • ✔ Generate indicators (KPIs)

What this tool does not do

  • ✘ Replace engineering judgment
  • ✘ Connect to Jira or any external system
  • ✘ Send data anywhere without asking first — everything stays local until you review and confirm an email send

How to test

  1. Open Gate 1 and enter a few changes (or load the demo project below).
  2. Move to Gate 2 and decide what gets approved.
  3. Authorize releases in Gate 3.
  4. Group authorized items into a Deployment batch.
  5. Check Results & KPIs.
  6. Share your feedback using the 📋 Share Feedback button above — it takes about 2 minutes and helps validate the framework.

Gate 1 — Triage

Classify each change. Priority is calculated automatically.

Priority Formula
priority = (severity_weight × 3) + (scope_weight × 2) − complexity

Severity weights: P0=4, P1=3, P2=2, P3=1. Scope weights: Network=4, Client=3, Site=2, Single Unit=1. Bands — Fast-Track (≥18), Standard Review (10–17), Deferred (<10).

Core KPIs

Release Health Index (RHI)

A composite index proposed as part of this framework: safety approval rate, complexity (inverted), rollback readiness, and deployment success, combined into a single 0–100 score.

Exploratory composite indicator; weights have not yet been externally validated.

RHI Formula
RHI = (Safety Rate×30) + ((1−Avg.Complexity/5)×20) + (Rollback Readiness×30) + (Deployment Success×20)
